# 프론트엔드 아키텍처 & 컨벤션 설계 최종본

> 대상: `frontend/`  
> 기술: Vite, React, TypeScript, Tailwind CSS, shadcn/ui, React Router, React Joyride, Kakao Maps  
> 목적: 지역 병원 길잡이 확장 프론트를 유지보수 가능한 구조로 관리한다.

## 1. 사용자 기준

주 사용자는 어르신과 보호자입니다. 따라서 디자인 판단은 다음 기준을 우선합니다.

- 지도는 항상 화면의 중심 기능으로 보이게 한다.
- 글씨, 버튼, 병원 카드, 마커는 모바일에서 먼저 읽히는 크기로 만든다.
- 긴 세로 스크롤보다 고정 지도 + 하단 패널 전환을 우선한다.
- 도움말은 별도 사용법 페이지가 아니라 React Joyride로 화면 위에서 안내한다.
- 초록색 중심 UI는 지도와 겹쳐 잘 보이지 않으므로 주요 색은 파란색, 위험 안내는 빨간색으로 구분한다.

## 2. 현재 구현 구조

```text
frontend/
├── src/
│   ├── main.tsx                  # RouterProvider 조립
│   ├── router/index.tsx          # createBrowserRouter 라우트 정의
│   ├── pages/
│   │   ├── HomePage.tsx
│   │   ├── TriagePage.tsx
│   │   └── NotFoundPage.tsx
│   ├── components/
│   │   ├── templates/AppShell.tsx
│   │   ├── organisms/
│   │   ├── molecules/
│   │   └── ui/
│   ├── hooks/
│   ├── api/
│   ├── lib/
│   ├── types/
│   ├── utils/
│   └── constants/
├── package.json

```

## 3. 라우터 규칙

- 라우터는 반드시 `src/router/index.tsx`에 분리한다.
- `src/main.tsx`는 `RouterProvider`만 렌더링한다.
- 공통 레이아웃은 `AppShell`에서 관리하고 화면은 `Outlet`으로 렌더링한다.
- 현재 라우트는 `/`, `/triage`, `*` 세 가지다.
- 404 화면에는 처음 화면과 진료 안내로 돌아가는 명확한 버튼을 둔다.

## 4. 레이어 규칙

| 레이어 | 책임 |
|---|---|
| `pages` | 화면 조립, 데이터 훅 호출, 탭/패널 상태 |
| `templates` | 공통 레이아웃, 네비게이션, Joyride |
| `organisms` | 지도, 폼, 병원 목록 같은 큰 UI 섹션 |
| `molecules` | 병원 카드, 위치 버튼, 상태 줄, 뱃지 |
| `ui` | shadcn/ui 기반 프리미티브 |
| `hooks` | geolocation, nearby, triage, Kakao map lifecycle |
| `api` | FastAPI 요청 함수와 axios 인스턴스 |
| `lib` | Kakao SDK, geolocation, env 같은 비순수 어댑터 |
| `utils` | 포맷, severity 매핑, request 조립 같은 순수 함수 |
| `types` | API wire 타입과 공용 타입 |

컴포넌트는 `api`와 `lib`를 직접 호출하지 않고 훅을 통해 접근합니다.

## 5. 모바일 레이아웃 규칙

- 전체 앱은 데스크톱에서도 `max-width: 430px` 모바일 폭으로 중앙 정렬한다.
- `/triage`는 `100vh` 안에서 동작하게 하고, 문서 전체가 길게 늘어지지 않게 한다.
- 지도는 화면 뒤쪽에 고정하고, 정보 입력/목록/결과는 하단 패널에서 전환한다.
- 하단 패널은 `nearby`, `symptom`, `result` 탭으로 나눈다.
- 하단 패널 손잡이는 드래그로 위아래 조절하고, 탭하면 작은/중간/큰 높이로 순환한다.
- 패널 내부만 스크롤하고 전체 페이지 스크롤은 만들지 않는다.

## 6. 지도와 마커 규칙

- 내 위치 마커는 가장 높은 우선순위로 표시한다.
- 내 위치는 파란색 타깃 형태로 병원/응급실 마커와 명확히 구분한다.
- 병원 마커는 파란색, 응급실 마커는 빨간색으로 표시한다.
- 병원 정보창은 마커 클릭 또는 병원 카드 선택 시 열리게 한다.
- 지도 위 버튼과 범례는 하단 패널에 가리지 않는 위치에 둔다.
- 병원 목록 카드 선택 시 지도 중심 이동과 정보창 열기를 함께 수행한다.
- 응급·급한 상황을 전제로 하므로 기본 지도는 너무 넓게 축소하지 않는다.
- 주변 병원 기본 조회는 5km·5곳을 우선하고, 없을 때만 10km·5곳으로 확장한다.
- 기본 지도는 조회된 가까운 병원이 모두 보이도록 맞추고, `전체보기` 버튼에서만 최대 level 9까지 허용한다.

## 7. 도움말 규칙

- 사용 방법은 별도 페이지로 빼지 않는다.
- `react-joyride`를 사용해 실제 화면 요소 위에서 단계별로 안내한다.
- 앱 진입 후 첫 화면에서 자동으로 `/triage`로 이동해 도움말을 실행한다.
- 헤더의 `도움말` 버튼을 누르면 언제든 다시 실행할 수 있어야 한다.
- Joyride 타깃은 실제 렌더링되는 요소에 `data-tour` 속성으로 지정한다.

## 8. API 규칙

- `api/triage.ts`는 요청 함수만 가진다.
- axios 인스턴스와 인터셉터는 `api/instances`, `api/interceptors`에 둔다.
- wire 타입은 백엔드 응답의 snake_case를 유지한다.
- 요청 body 조립은 `utils/triageRequest.ts`에서 처리한다.
- 서버 상태는 `useTriage`, `useNearbyFacilities` 같은 훅에서 관리한다.

## 9. 네이밍 규칙

| 대상 | 규칙 | 예시 |
|---|---|---|
| 컴포넌트 | PascalCase named export | `FacilityCard.tsx` |
| 훅 | `use` + PascalCase | `useTriage.ts` |
| API 객체 | 도메인 + `Api` | `triageApi` |
| 유틸 함수 | camelCase | `formatDistance` |
| 타입 | PascalCase | `TriageResponse` |
| 이벤트 props | `onXxx` | `onSubmit` |
| 내부 핸들러 | `handleXxx` | `handleSubmit` |

default export는 사용하지 않습니다.

## 10. 검증 명령

```bash
npm run format:check
npm run lint
npm run typecheck
npm run build
```

UI 변경 뒤에는 브라우저에서 `/`, `/triage`, 없는 경로를 확인합니다. 지도 관련 변경은 카카오 키가 있는 환경에서 마커, 내 위치, 카드 선택, 패널 드래그를 직접 확인합니다.

## 11. 현재 제외 범위

- 관리자 화면
- 로그인
- 실제 병상 정보
- 병원 데이터 실시간 갱신
- PWA와 React Native
- 테스트 인프라

위 항목은 파일 삭제나 영구 제외가 아니라 현재 과제 확장 MVP에 포함하지 않는다는 뜻입니다.
